## Unreleased

- M75 POL-LAST: the last polish items. `world.bake_cell_hlods` with `outDir` `"."` writes `0_0.glb` (no leading slash) and its docs say when `note` and `indexWritten` are there; a proxy retry that is not relaunched keeps its one warning flag, and the loader builds its "did you mean" text only for the first try. Hi-Z no longer culls for captures, camera views or render targets (it runs only on the main camera's frame), and the debug-line draw binds the three extra quad views (no more sokol validation errors); `portal_mesh_seen` scales its margin with the coordinate; `foliage.*` result docs name `historiesPruned?`; Save in the Cells panel says when the index on disk could not be read; the foliage brush slider no longer overwrites the density that the radius clamps, and the editor's candidate budget is the command's own constant. The autotest of the AI orchestrator's continuation records its invocations in a file of its own (a shared name counted another autotest's runs).
- M75 POL-STREAM: the polish of the HLOD proxies (docs/BIG_WORLDS_STREAMING.md, "HLOD proxies"). A proxy that cannot be read is tried again after 120 fixed ticks while its cell is in range (one warning only) and forgotten when the cell leaves it, instead of staying failed until the scene reloads; a proxy file that vanishes between the check and the read fails the job ("file vanished"); the errors of a proxy read name `hlod.load` and hint at `world.bake_cell_hlods`; proxies no longer cast shadows; the streamer picks the 512 nearest proxies with a partial selection instead of sorting every candidate each tick. `world.bake_cell_hlods` refuses an absolute or escaping `outDir` before writing anything and its result carries a `note` that a running game picks the new proxies up after a scene reload; the `proxy` field of `world.cells` and the `hlod*` fields of `world.stream_status` are documented.
- M75 POL-RENDER-A: render polish. Custom shaders: a program with too many textures in one stage now names each stage over its limit (both when both are), says that D3D11 and Metal refuse it too, and tells apart the material's own textures from the engine's by name, not by a `tex` prefix (docs/CUSTOM_SHADERS.md, "Errors that teach"). Floating origin: `World::set_origin` and `clear()` tell the origin observers, a capture follows the game world's rebases, fog and volumetric heights are subtracted in double, `originShifts` counts only what an initialized renderer followed. Hi-Z: a capture keeps its own pyramid and restores what `render.occlusion` shows, the age limit counts fixed steps (48) whatever `fixedHz`. Areas and portals: new `Camera.areaCulling` (default true; false draws every room, as a map camera needs), the boxes are gathered once per frame and a mesh is rejected against the areas' bounds first. Foliage: the cap of 262144 instances is shared by every entity (nearest chunks first), the instances of two worlds with the same entity numbers no longer reload each other, shadow-only instances are not counted in `meshesCulled`, a Foliage whose fields went invalid at run time warns once, `Tree.GLB` finds `Tree.lod1.glb`, and the stale "stays 0" texts of `renderStats` are gone.
- M75 POL-EDITOR-C: the polish of the cells, HLOD and foliage editor tools. Saving cells keeps the `hlod` entries `world.bake_cell_hlods` wrote into the index while the cells were open (the index is read again before it is written), a note_edit with no entity marks every live cell unchecked, and the transient `hlod i,j` proxy entities are neither listed in the Hierarchy nor picked in the viewport. The foliage brush sends fewer stamps per `foliage.paint` piece when radius times density would pass the command's 16.7 million grid cells (at least one), the density slider stops where one stamp still fits (the panel says so, and warns when the ScatterRule's density is too high for the radius), a first piece that changes an unreadable instances file and makes no undo step marks the scene unsaved and says so, and the results of the foliage commands list `historiesPruned` (the ids whose history went with a deleted entity) so the editor takes those undo rows out quietly instead of leaving rows that fail after an Undo of the delete. The brush inverter is documented as Ctrl, Cmd on a Mac (Dear ImGui swaps them, so Ctrl+click is not needed), for the foliage and the terrain tools. The undo rows pass drops nothing without rebuilding the stacks, the world split compares the scene's file once, and autotest F3 counts the history's own `undoDepth` and `historyLost`.
- M75 P1e: streamed cells that are not loaded draw their HLOD proxy (docs/BIG_WORLDS_STREAMING.md, "HLOD proxies"). A cell of the world index may name `hlod: {mesh, maxDistance?}` (a `.glb` in the space of the cell's corner; every index writer keeps it, wrong entries are errors with their JSON pointer, a missing file a warning). With the new `StreamedWorld.hlodDistance` above 0 the streamer reads the proxies of the (at most 512) nearest cells within that distance of an anchor in the background, shows each as a transient entity `hlod i,j` (its `streamedProxy` flag is set; never saved) at the cell's absolute corner while the cell is not in the world, and hides it in the same call that adds the cell's entities, so no frame draws both; it follows the floating origin and counts in `renderStats.hlodProxies`. A proxy that cannot be read logs one warning and draws nothing. There is no cross-fade between the proxy and the cell. `world.cells` shows `proxy` per cell and `world.stream_status` the proxy counts. New command `world.bake_cell_hlods {world, outDir, cells, ratio | maxError, maxDistance, dryRun}`: it merges and simplifies every cell (the code of `world.bake_hlod`), writes deterministic `<outDir>/<i>_<j>.glb` files and then names them in the index with one atomic write.
- M75 P6c-b: the foliage brush in the editor (View > Foliage tool, docs/editor/EDITOR_FOLIAGE.md, docs/BIG_WORLDS_TERRAIN.md "Editing foliage in the editor"). With a `Foliage` selected (or a terrain with one on it) Add and Remove paint with the shared brush (Ctrl swaps them; radius, density or the rule's, one mesh), Scatter all and Clear (it asks first) work on the whole field, and a ring follows the terrain; a stroke is ONE editor undo row (`foliage.undo` / `foliage.redo`) however many pieces it was sent in, Esc takes it back and a click that misses the terrain keeps the selection. `foliage.paint` takes `points` (up to 512 stamps, `kMaxFoliagePaintPoints`): one call, one rewrite of the instances file and one history step for a stroke, the same instances as one call per point; the editor sends a piece at most every 0.2 s (twice the last call's duration when longer, up to 3 s) because every piece rewrites the whole file (52 MB at 2,000,000 instances). The results carry `historyId` and `historyLost`, the histories of destroyed entities are pruned, and all of them together keep 512 MB (`kFoliageHistoryTotalBytes`, `historiesEvicted`). The editor numbers each foliage undo row with its history's id and the step's absolute number and drops the rows of steps the history let go of (or all of them on `historyReset`, `stale_history` or an eviction) with a toast that names the limits, keeping the other commands of a Chain entry. The schemas of `foliage.scatter` and `foliage.clear` refuse `continueStroke`, and a `foliage.paint` with it makes no undo row of its own (it joined the newest step). New autotest section F3.
- M75 P1d: the HLOD proxy is drawn (docs/BIG_WORLDS_LOD.md, "Levels of detail"). A `LodGroup` with `hlodProxy` (a mesh) and `hlodThreshold` draws that one mesh with the group's matrix instead of its children once the group is past the threshold (in the unit of its `mode`, measured on the group's whole bounds): the children are skipped in the main pass and in the shadows, the proxy casts the shadow, and with `crossFade` above 0 the switch uses the same dither as a LOD switch. An unreadable proxy draws the children as before and logs one warning with the entity and the path. New `renderStats.hlodProxies`, `render.supports` `hlod`, and `world.bake_hlod {entity | scene + root, out, ratio | maxError, apply}`: it merges every mesh under an entity into one in the entity's local space (materials kept as submeshes), simplifies it with the simplifier of `model.generate_lods` and writes a deterministic `.glb`; with `apply` it sets `LodGroup.hlodProxy` and a default `hlodThreshold` (one undo step in the editor). A scene with no `hlodProxy` pays one empty-string check per `LodGroup`. The proxy of a streamed cell that is not loaded is not drawn yet (P1e).
- M75 POL-TERRAIN-A: the polish of the terrain tool (docs/editor/EDITOR_PANELS.md "Terrain tool", docs/BIG_WORLDS_TERRAIN.md). Play and Stop no longer keep what the game did to a terrain: Play edits a copy (`TerrainHeights::clone`) and Stop gives back the editor's heights, holes and splat maps exactly. `terrain.sculpt|paint|holes|generate` from the Console, the AI or MCP are undo entries (`terrain.redo` / `terrain.undo`), the oldest ones are dropped, with a toast, when the terrain's 64 steps no longer cover them, and undo and redo of the first holes or paint stroke take the `Terrain.holes` / `Terrain.splatMaps` paths back and make them again (`TerrainStep::created`; a file already written stays). `extend_step` copies only the new piece; the brush ray costs one matrix inverse per frame; the brush radius limit counts texels of the plane being edited (a finer splat map allows a smaller radius); a failed piece is reported once; Esc gives back the unsaved state; a click that misses the terrain keeps the selection and the tool; the export, phone, play session, project browser and review checks count unsaved terrain edits. Autotest T3 moves a floating panel off the viewport and checks Esc, a miss click and Play/Stop.
- M75 POL-EDITOR (the review of P3c): a cell save that fails (a write rule, an index the save would make invalid) now leaves the editor as it was (no cell made, no entity re-filed); an edit checks the cell of the edited entity first and the other loaded cells one per frame, instead of every cell at once; deleting the root of a cell with unsaved changes keeps it unsaved and empty (Save writes it empty, Undo brings it back) instead of dropping the changes; a saved cell's 3D height bounds follow its entities (they shrink too) and the `sizeBytes` the index lists follows the file; cell list ids no longer overflow for large coordinates; Export, Phone, the AI play session, the Project browser and the Review sheets count unsaved terrain like the quit dialog; `world.merge_cells` returns `warnings` for a `StreamedWorld` that stays in the merged scene (with how to remove it) and compares `out` with the world's files without regard to case on Windows and macOS.
- M75 POL-TERRAIN-B: terrain polish (docs/BIG_WORLDS_TERRAIN.md). The holes are their own R8 texture, one byte a cell, read by the vertex stage (16.8 MB for 4097 x 4097), no longer a third slice of the control array: the control array is the splat maps only (at most 2 x 64 MB, it was up to 192 MB), and the fragment stage still reads 16 of 16 texture units (now pinned by a test that says what to do when a pair is added). A paint stroke copies only the texels it changed (sub-rectangle copy through a staging buffer) instead of sending the whole control array, and the layer pictures are decoded and their mips packed by a job off the render thread (a terrain draws neutral layers until the job is adopted; `Renderer::wait_terrain_loaded()` for tests and captures; `Renderer::terrain_uploads()` has `splatRects` and `layerLoads`). The texture-size error and its hint give the same limit and the largest side that fits. Rewriting the heightmap file and reloading the asset now replaces the heights (the file is read with no lock held; unsaved edits win), `TerrainSplat` has `mark_dirty` / `dirty_since` like the heights, and a Terrain whose own `Collider3D` is disabled no longer gets the terrain's collider switched on. The terrain collider's layer, mask and friction and why it keeps its own copy of the heights are documented.
- M75 POL-EDITOR (the review of P3c): a cell save that fails (a write rule, an index the save would make invalid) now leaves the editor as it was (no cell made, no entity re-filed); an edit checks the cell of the edited entity first and the other loaded cells one per frame, instead of every cell at once; deleting the root of a cell with unsaved changes keeps it unsaved and empty (Save writes it empty, Undo brings it back) instead of dropping the changes; a saved cell's 3D height bounds follow its entities (they shrink too) and the `sizeBytes` the index lists follows the file (the index was already written atomically, through a temporary file and a rename: that did not change); cell list ids no longer overflow for large coordinates; Export, Phone, the AI play session, the Project browser and the Review sheets count unsaved terrain like the quit dialog; `world.merge_cells` returns `warnings` for a `StreamedWorld` that stays in the merged scene (with how to remove it) and compares `out` with the world's files without regard to case on Windows and macOS.
- M75 POL-EDITOR-B: the second polish of the terrain tool and the streamed cells (docs/editor/EDITOR_PANELS.md "Terrain tool" and "Cells panel", docs/BIG_WORLDS_TERRAIN.md). A `terrain.undo` run by hand no longer makes the editor drop a terrain step that still works: every terrain undo of the list carries the absolute number of its step and the editor drops only those the terrain's history let go (`TerrainHeights::history_lost`), whatever the list trimmed or a snapshot absorbed; a dropped step is taken out of its entry only, so a Chain entry keeps its other inverses, and the toast names the real limits (64 steps / 256 MB). Esc in the terrain tool checks the cells again, a click that misses the terrain says so in a tooltip, and the autotest fails (instead of skipping) when the corner it clicks has ground. Saving right after an edit the editor could not attribute looks at every loaded cell first, so a dirty cell is written; a cell whose root was deleted before its check counts as unsaved (one checked since its last edit just closes, whoever deleted the root), one whose file is empty is closed instead of kept as an unsaved empty slot, and the Cells panel disables Select on a row whose root is gone. `world.merge_cells` compares `out` with the world's files with one lookup of `out` and judges long Windows paths through `fs::os_path`.
- M75 P1c: impostors are drawn (docs/BIG_WORLDS_LOD.md, "Impostors"). `model.bake_impostor {model, views?, resolution?, mode?, apply?, overwrite?}` draws a baked model from `views` x `views` directions (octahedral, or hemiOctahedral for the upper half only) into `<name>.impostor.png` (colour, straight alpha), `<name>.impostor.normal.png` (model-space normals) and `<name>.impostor.json` (`factoria.impostor/1`), the same bytes on every platform; `resolution` is now the pixels of the whole atlas side (default 1024, up to 4096), `apply` only changes the loaded scene. With `MeshRenderer.impostor` set and `impostorDistance` above 0 (in the unit of `lodMode`), the entity beyond it is drawn as ONE camera-facing instanced card that blends the three nearest frames of the atlas, lit by the atlas normals (sun, lights, fog; `unlit` is honoured) with an alpha cutout, replacing the last level of `lods`. `lodCrossFade` fades it with the same dither as two levels, a shadow-casting entity casts a simple camera-facing card shadow, and a missing, invalid or wrong-sized atlas gives one warning that names `model.bake_impostor` while the last level keeps drawing. New shader set `impostor` (GL, GLES3, WebGL2, D3D11, Metal), `renderStats.impostors` counts the cards (not in `meshes`), `render.supports` `impostors` is true, a new bench `render.impostor3d`. A scene with no impostor pays one flag. Pure atlas maths in `fa/scene/impostor.h`.
- M75 P2c: `OcclusionArea` and `OcclusionPortal` work (docs/BIG_WORLDS_LOD.md, "Areas and portals"). With an enabled `OcclusionArea` in the scene, each main-view camera starts in every area whose box holds it (and both sides of the open portals that hold it), walks through the open portals whose box is in view, narrowing the view to each portal's screen rectangle (cycles, a depth of 32 portals and 4096 tests are guarded), and leaves out of the main pass the meshes none of whose areas it reached (a mesh belongs to every area its bounds touch, and to the outside unless wholly inside one box; area 0 counts as an area). A closed portal blocks the walk; shadows, probes, foliage and 2D are not culled; a scene with no OcclusionArea takes the old path. New `renderStats.portalsVisited` and `meshesCulledByArea`, `render.supports` `occlusionPortals` (true on every backend). A portal that names an area no OcclusionArea has (with a did-you-mean), a portal from an area to itself and an area with an id outside 1..65535 are reported once.
- M75 P6b: `foliage.scatter {entity, rule?, dryRun?}`, `foliage.paint {entity, center, radius, mode?, density?, mesh?, seed?, rule?, continueStroke?}`, `foliage.clear {entity, region?}`, `foliage.undo {entity}` and `foliage.redo {entity}` work (docs/BIG_WORLDS_TERRAIN.md, "Foliage commands"). Scatter fills the instances file of a Foliage from a `ScatterRule` over a Terrain: a jittered grid hashed from the seed (the same bytes on every platform), rejected by slope, height, layer, hole and `minSpacing`, with the counts by reason; paint adds or removes instances in a circle; clear empties the file or a rectangle. Each edit is a step of an in-memory history per Foliage entity (64 steps, 128 MB; a step stores only the changed instances, `historyDropped` says when the oldest go) and returns `undo` (`{command: \"foliage.undo\", args: {entity}}`); `foliage.paint` with `continueStroke` joins the newest step, so one brush drag is one undo; the editor's Undo/Redo menu runs the pair; the history is not saved; a scene reload closes it only when the file or the fields differ from what the last step left, and so does an outside change (`stale_history`). There is no `foliage.restore`. `TerrainSampler` (fa_scene) reads a terrain's heights and layers with the matrices fetched once, so scatter of 2 million candidates reads the ground faster; `minSpacing` uses a flat grid; slope is compared as tan squared. The editor brush is M75 P6c-b.
- M75.2b occlusion culling on the GPU with a depth pyramid (docs/BIG_WORLDS_LOD.md, "Occlusion"). New `SceneSettings.occlusionMode` (`cpu` default, `gpu`, `auto`): with `gpu` (or `auto` on a backend with compute shaders: D3D11, Metal, OpenGL 4.3) a perspective camera draws its depth and normal prepass every frame, a compute pass reduces it to a 256-cell-wide grid of nearest and farthest depths, the grid is read back without waiting, and every mesh whose box lies behind fully covered cells is left out of the main pass, with no `Occluder` needed. The depth is one frame old (the boxes are tested in the old camera's pose and widened by what the camera's move can reveal): a mesh that comes out from behind another shows one to two frames late, and a camera cut, a zoom or a fast move draws everything; shadows are not culled, camera `showTags`/`hideTags`, several cameras (up to 8), probes and the floating origin are handled. GLES3, WebGL2 and macOS OpenGL keep the CPU path (`gpu` warns once, `auto` is silent); the web player is not bigger. `render.supports occlusionGpu` is true where it runs, `renderStats.occlusionTests` and `meshesOccluded` count it, `render.occlusion` has a `gpu` object and a `level` argument, the debug view `occlusion` shows the culled boxes and a coarse mip, and the bench `render.hiz3d` measures it. A scene on the default mode is unchanged. New `// shdc-slang:` first-line override in `tools/shaders/compile_shaders.sh`.
- M75 P6a: foliage is drawn (docs/BIG_WORLDS_TERRAIN.md "Foliage"; `renderer.supports` `foliage` is `true` on every backend, no compute shader). `Foliage.instances` is a versioned little-endian file (`fa/scene/foliage.h`: `read_foliage`, `write_foliage`, 16-byte header, 26 bytes per instance, up to 2000000; a bad file is an error naming the byte and the fix) that the renderer reads on a worker thread and reloads when it changes on disk, so a big field never stalls a frame (a missing or invalid file draws nothing and is warned about once). The instances are chunked in 32 m cells, culled by distance, frustum and the CPU occlusion buffer, faded out between `fadeStart` and `fadeEnd` with the dither of the LOD cross-fade (8 steps, no blending), switched to `<name>.lod1.glb` beyond `lodDistance`, thinned stably by `density`, swayed by `windStrength` (a CPU shear: the top moves, the base stays) and, with `castShadows`, put into the shadow maps (also from chunks just outside the view). Instances of one mesh and LOD are one instanced draw; at most 262144 per camera (nearest chunks first, a warning past it). `renderStats.foliageInstances` and `foliageInstancesCulled` count them. A scene with no `Foliage` pays nothing. `foliage.scatter`, `foliage.paint` and `foliage.clear` stay `not_built` (M75 P6b).
- M75 P5c: terrain brushes in the editor (View > Terrain tool, docs/editor/EDITOR_PANELS.md "Terrain tool"). With a `Terrain` entity selected and a mode on, the viewport drags a brush instead of the gizmo: Sculpt (raise, lower, smooth, flatten with a height you can pick from the ground), Paint (a layer picked from the list with its albedo thumbnail) and Holes (cut or fill), with radius, strength and falloff, a cursor ring that follows the relief (and an inner ring where the effect is full), `[` `]` for the radius and Shift+`[` `]` for the strength, Ctrl for the opposite effect and Esc to take a stroke back. A stroke is a stamp every radius / 4 applied live as `terrain.sculpt|paint|holes` calls and ONE editor undo step (`terrain.undo` / `terrain.redo` on the editor's stack, Ctrl+Z works, the scene is marked changed). New command arguments: `continueStroke` on the three edit commands (a call adds its changes to the newest terrain undo step, so a live stroke costs one of the 64 steps of the history) and `falloff` (0 ... 1) on `terrain.sculpt` and `terrain.paint`; `TerrainHeights::extend_step` in `fa/scene/terrain.h`. The editor keeps a terrain's unsaved edits and history across a snapshot undo, Play and Stop; Save writes the terrain files and says why when one cannot be written (and now keeps the editor open on a failed "Save and quit"); closing, reloading and opening another scene ask when a terrain has edits not written yet. The brush maths (settings, stamps along the path, ring, ray to the ground) is the shared `tools/editor/src/brush.h`, which the foliage brush reuses. Editor autotest section T3.
- M75 P3c: editing a streamed world (docs/BIG_WORLDS_STREAMING.md "Editing a streamed world", docs/editor/EDITOR_PANELS.md "Cells panel"). `world.split_cells {scene, cellSize, out?, dimension?, overwrite?, dryRun?}` cuts a scene into a world index, one scene per non-empty cell and a persistent scene (global entities and the scene's settings; the index's new optional `persistent` key names it), and `world.merge_cells {world, out, overwrite?, dryRun?}` joins them back with the same entities and ids (they were `not_built` stubs); both follow the project write rules and never change the files they read. The editor's View > Cells panel loads cells as editable entities (the cells around the camera, nearest first, or the ones you pick; nothing streams by distance in Edit mode and an edited cell is never lost), marks the cells with unsaved changes (Undo back to the saved state clears the mark; the editor's undo snapshots carry the loaded cells), draws the cells in the viewport (green loaded, orange unsaved, grey not loaded), shows an entity's cell in the Inspector and asks before unloading an unsaved one. Save writes only the changed cells, each to its own file, and the index only when a cell was added or its height bounds grew; an entity moved into another cell is re-filed into that cell's file at Save (moving an entity needs no command of its own). Play streams as the game does and Stop brings the loaded cells back. New editor autotest section W2.
- M75 P3b: tilemap chunks as the cells of a streamed 2D world (docs/BIG_WORLDS.md "Tilemap chunks"). `tilemap.split_cells {scene, tilemap?, cellSize?, out?, overwrite?, dryRun?}` cuts one big Tilemap into a `"dimension": "2d"` world index and one chunk scene per cell (`cellSize` in tiles, deterministic, the source scene untouched, empty cells not written). Chunks line up with no rendering seam, and 2D physics drops the contacts of the hidden edge between two chunks' boxes, so a body slides over a border as over the unsplit map; autotile is baked in the tiles, so a split map has the same tiles. `project.validate` compares the chunks of a 2D index (tileset, tile size, grid, cell bounds).
- M75 P5d: the terrain draws its layers and its holes (docs/BIG_WORLDS.md "Terrain"). Up to 8 `Terrain.layers` are blended per pixel by the two RGBA `splatMaps` (weights bilinear and normalised; no map = layer 0 everywhere): the albedo and normal textures are 2D texture arrays with mipmaps, `roughness`, `metallic` and `normalScale` are per layer, a missing texture leaves its layer neutral, and a layer texture of another size is an error naming `/layers/3/albedo` and both sizes. `holes` is cut in the geometry (a terrain with holes draws a patch of 4 vertices per cell and the vertex shader collapses the cell), so the surface, its shadow and the depth prepass lose it and `terrain_sample` / `terrain_height_at` report no ground there (a change: they used to answer every point of the grid); at a coarse level of detail the middle cell of a quad decides. A sculpt now uploads only the rectangle it changed to the height texture (the first one converts the texture, whole). The normals take 12 height fetches a pixel instead of 16; terrain items have a sort key (no slow comparator for the whole frame); a dangling cached layer texture after `Assets::clear` or a reload cannot happen (the renderer owns the arrays); `render.supports` has a `limits` object (`maxTextureSize`, `maxArrayLayers`, `maxArrayTextureSize`). New `terrain_splat_weights`, `terrain_layer_weights` and `load_terrain_layer_images` in `fa/scene/terrain.h`, the `render.terrain3d` bench, and `Renderer::terrain_uploads()`.
- M75 P1a: levels of detail are drawn (docs/BIG_WORLDS.md, "Levels of detail"). `MeshRenderer.lodMode` `screenSize` picks the entry of `lods` by the size the object covers on the screen (the diameter of its bounding sphere over the height of the view), and the new `LodGroup` shows one child of its entity by `thresholds` in either unit (only that child's meshes are drawn). The camera of the main view chooses every level; shadows and the probe and GI captures draw the level it chose, and a split-screen camera, a `CameraView` or a render target chooses for its own view. With `MeshRenderer.lodCrossFade` or `LodGroup.crossFade` above 0 a switch is a dithered cross-fade over that many seconds: both levels are drawn through complementary screen-space dithers (a `discard` driven by a per-draw number, no blending; only the draws that fade have a program with it: four variants of the engine's own mesh and prepass programs, `mesh_lod`, `mesh_skin_lod`, `prepass_lod`, `prepass_skin_lod`, about 275 KB more of embedded shader source in the player, or the `discard` a custom `alphaMode` `"clip"` material already has, so the other draws keep their early depth test on a tile-based GPU), the shadow passes draw the new level only, a fading entity is drawn outside its instanced batch, and a mesh with a full-shader material, a custom material that is not `"clip"` or subsurface scattering switches at once. `renderStats.lodCrossFades` counts the meshes drawn in the main view as a level of a fade (two per fading entity, summed over the cameras) and `render.supports` `lodCrossFade` is true on every backend. A scene with no `lods` and no `LodGroup` draws with the programs it always had and checks one flag. New pure functions in `fa/scene/lod.h` (`lod_level_of`, `lod_group_level`, `lod_fade_step`, ...). The mesh template changed (`mesh_common.glsl`), so every compiled material twin of a game must be re-exported; the HLOD proxy and the impostors stay without effect.
- M75 P5b: the terrain commands are real (docs/BIG_WORLDS.md "Terrain commands"; they were `not_built` stubs). `terrain.create` writes a flat 16-bit PNG heightmap and the `Terrain` entity that uses it; `terrain.sculpt` (raise, lower, smooth, flatten), `terrain.paint` (8 layers in two RGBA splat maps, weights renormalised to 255), `terrain.holes` (an 8-bit mask, 1 pixel per cell) and `terrain.generate` (seeded noise plus hydraulic and thermal erosion) edit the shared heights live, honour the terrain's transform, are deterministic and make ONE undo step each (`terrain.undo`, `terrain.redo`, bit for bit); the files are written by `save: true`, `terrain.save` or any scene save, atomically. The physics collider honours the holes mask. Errors name the JSON pointer and the fix; brush and erosion limits are work counts, not times. - M75 P4b: the renderer follows the floating origin (docs/BIG_WORLDS.md "What the renderer does"): the frame of a `World::rebase` is the frame without it, with no smear, flash or jump. - M75 P1b: automatic LOD chain on model import (docs/BIG_WORLDS.md "Automatic LOD chain"). `gameReady.lodChain` (`enabled`, `levels` 1..7, `ratios`, `errors`, `screenSizes`, `minTriangles`, `lockBorder`, `normalWeight`, `uvWeight`) makes deterministic simplified copies with meshoptimizer, written as `<name>.lodN.glb` and a prefab whose `MeshRenderer` has `lodMode: "screenSize"` and `{mesh, screenSize}` entries; levels under `minTriangles` are skipped with a note. `model.generate_lods` is real (it was a `not_built` stub; `maxError`/`errors` and `dryRun` added, `apply` dropped) and `model.import_clean` takes `lodChain`. Skinned meshes are refused with a message.
- M75.2 occlusion culling on the CPU (docs/BIG_WORLDS.md, "Occlusion"): an enabled `Occluder` (box or mesh) now hides the 3D meshes behind it. Each main-view camera rasterises the occluders into a 256-cell-wide depth buffer on the job system (the same bytes with any thread count; caps of 4096 triangles per Occluder and 65536 per camera, a warning names what was cut) and leaves out of the main pass the meshes whose bounding box is proved hidden; it is conservative (a box that crosses the near plane or holds the camera is drawn), and shadow passes, sprites and 2D are not culled. `renderStats.occluders`, `occlusionTests` and `meshesOccluded` count it, `render.supports` `occlusionCpu` is `true`, and the new command `render.occlusion {save?}` and the debug view `render.debug_view {"view":"occlusion"}` show the buffer and the culled boxes. A scene with no enabled Occluder takes the old path. `OcclusionArea`, `OcclusionPortal` and the GPU path stay planned.
- A shader program that reads more than 16 image-sampler pairs in one stage (the units GLES3 and WebGL2 guarantee) is rejected with the count, which ones the engine's own bindings and the material's textures take, and what to drop.
- M75 P4a: the floating origin works (docs/BIG_WORLDS.md "Floating origin", the renderer follows in M75 P4b). Off by default; scenes and tests are unchanged.

- M75 P3a (streaming, docs/BIG_WORLDS.md, "Streaming"): a world is an index `<name>.world.json` (`schemas/world.schema.json`; `dimension` 3d on XZ or 2d on XY, `cellSize`, `origin`, per cell `coord`, `scene`, absolute `bounds`, optional `sizeBytes`; validated with the file, the JSON pointer, duplicate coordinates, missing files with "did you mean" and bounds outside their cell) plus one scene file per cell.
