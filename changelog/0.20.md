# What's new in FactorIA 0.20

The 0.20 releases, newest first. The newest version is in [CHANGELOG.md](../CHANGELOG.md).

## 0.20.0

FactorIA 0.20.0 (M90) fixes what an outside review of the engine found. The MCP server speaks protocol 2025-06-18
properly: a result is sent once as JSON text, capped at 80 KiB with a note naming the paging arguments, a cancel stops
the request it names, a malformed message gets a JSON-RPC error instead of ending the server, and the editor's endpoint
bounds its connections. Entities destroyed this frame refuse a new parent or id, capsules and hulls get the inertia of
their shape, store and ads requests end with an error when a backend never answers (a late purchase still arrives), the
audio callback allocates nothing, golden images fail when they are missing or differ in a region, and the docs that
contradicted the engine or each other are fixed.

### Changes

- **For game authors and AIs (M90.1):** the docs that broke or contradicted the engine are fixed against their source: recipe 9.27 reads `this.map.tilemap.component`; `Math.random` is deterministic in game scripts (and the seeded `Math.random` and fixed `Date` are those of `assets.animate_svg` modules); the NDK version, signing state, presets, menu bar Export, `--single-file` and `setup launcher` in GETTING_STARTED, BUILDING, EXPORTING and CLI.md; the seven AI roles, golden paths and repository layout in ARCHITECTURE; the tool counts in MCP, AI_PROVIDERS and AI_COSTS; EXTENDING's command areas from the registry. README gives the current status and every licence; the Spanish translations say what they lack.
- **For game authors and AIs (M90.4b):** a torus has at most 256 `segments` and 128 `sides`, the same range in the `model.*` schema and in the builder (a larger value used to be clamped at 512 and 256); `Shape2D.sides` and `points` share one 3..64 range. `game.device.gpuBackend` is `metal`, `d3d11`, `glcore`, `gles3`, `headless` or `unknown` (the `wgpu` and `vulkan` names the engine never builds are gone). `docs.list` lists `components` once and `docs.read components` returns the bundled COMPONENTS.md; its enum cells are escaped once and integer ranges print without `.0`.
- **For game authors and AIs (M90.4a):** an entity destroyed this frame refuses a new parent, a new child and a new id: `scene.set_parent`, `setParent` and `World::set_parent` say so (a teaching error, or a warning from C++) instead of leaving ids that disagree with the subtree about to go. Capsule and convex bodies now have the inertia of their solid shape (a capsule of radius r and half segment h: cylinder plus two hemispheres; a hull: its volume integral about the model origin, products of inertia ignored) instead of their bounding box, so a thin capsule spins about its axis faster than across it, as a real one does; boxes and spheres are unchanged. A request the store, ads or http backend never answers is ended by the engine with the error `network` after 30 s (300 s for the calls that wait for the player, 600 s for the ads consent flow, the request's `timeout` plus 5 s for `http.fetch`); the fake backend has no deadline. A `purchases.buy` or `restore` that the store completes after its deadline is not lost: it reaches the game as a `purchase` event and its transaction can be finished. The events a backend sends wait in a queue of at most 1024 (the answers 4096): the oldest are dropped (overlay, player and remotePlay events before any purchase), counted in `platform.state()` (`droppedEvents`) and reported once in the log. `world.spawn` and `world.spawnPrefab` (and the `scene.spawn` command) refuse a parent that is being destroyed, before creating anything. docs/PLATFORM.md, "Deadlines".
- **For engine code (M90.4a):** a `pattern` in a JSON schema is compiled once, in a process-wide thread-safe cache, instead of at every validation; an invalid pattern is still an error at the point it is used, and `check_schema_patterns` (fa/core/json_schema.h) finds one at load: `CommandRegistry::add` logs it. `CommandRegistry`'s nesting depth is kept per thread, so a command called from a job thread no longer sees the main thread's depth; the `set_before_call` hook runs only for the outermost call of a thread, and never on a job worker thread. `World::check_set_parent` says why a re-parent would be refused. `PlatformServices::set_request_timeout`, `set_clock` (tests use a fake clock) and `PlatformBackend::cancel` (the plugin adapter drops the request it waits for). A schema `pattern` that makes `std::regex_search` throw is a validation error, not a crash.
- **For engine developers (M90.5):** the audio callback allocates nothing while it mixes: the per-block flags of the buses (`used`, `live`, `ducking`), the bus buffers and the ducking gains are scratch made when the bus table is built (`set_buses`), not in the callback; a test counts the heap allocations of the mixing thread (`engine/audio/tests/test_audio_realtime.cpp`). The callback still takes the mixer's lock. docs/SOUND.md, "The audio callback".
- **For AIs using MCP (M90.2):** a tool result is sent once, as the whole JSON in a text block on every protocol version (no `structuredContent`), and a picture as an image block after it. A result over 80 KiB of JSON is cut down before it is sent: arrays and objects keep their first items or keys, long strings their start (never inside a UTF-8 character), the JSON stays valid, and a `_truncated.note` says what was cut and names the paging arguments of the tool's own schema (`offset`, `limit`, or a camelCase name such as `pageToken` or `entityLimit` that takes an integer or a string) or, for a tool that does not page, the arguments that ask for less. `notifications/cancelled` now stops the request it names (a compound command or an `ai_run` sub-agent stops at its next step; over stdio a request still waiting for its turn is skipped; in the editor a scene command still waiting for the main thread is dropped) and that request gets no response (over HTTP an empty event stream, or 204); a cancel for an unknown or finished request is ignored. When a client closes stdin, a request still running 10 s later is cancelled. A malformed message (a `jsonrpc` that is not the string `"2.0"`, a non-string `method`, an object `id`, string `params`) gets a JSON-RPC Invalid Request and the server answers the messages around it; before, such a line ended `factoria mcp` and could take the editor's endpoint down with it. docs/MCP.md.
- **For AIs using MCP (M90.2):** the editor's MCP endpoint serves at most 16 connections at once, plus a spare that lets a cancel in when all are busy (the longest-idle keep-alive connection is closed to free it; more wait their turn, never a 503), says `Keep-Alive: timeout=5` and joins each connection's thread when it ends; a connection silent for 30 s is closed (408 for a half-sent request), and a body over 8 MiB gets 413 with a JSON-RPC error that says what to do instead. docs/AI_PROVIDERS.md, "CLI agents in the editor".
- **For AIs and users of CLI agents (M90.2):** the MCP config a Claude Code run gets is a file of its own (`.factoria/ai/fa-run-mcp-claude-code-<unique>.json`, private on Linux and macOS), deleted when the run ends, also after a crash or a cancel, so two runs at once no longer share one; a file Windows keeps open is reported and swept a day later by a later run, which removes only `fa-run-*` files (and the run files 0.19.0 left there under its older names). Argv placeholders are expanded in one pass (a prompt that contains `{model}` keeps it), and a `{prompt}` argument of a custom `claude-code` or `codex` template goes after `--`, so a prompt that starts with `-` is not read as an option (a `--` elsewhere in the template, such as a flag's value, is left alone). FactorIA's own MCP client (the `mcpServers` of ai.json) reads `structuredContent` first and cuts a long text result without breaking a UTF-8 character. docs/AI_PROVIDERS.md.
- **For engine developers (M90.3):** golden images are honest. A golden that does not exist now FAILS its test (it used to be written and the test passed); `FA_UPDATE_GOLDENS=1` writes goldens (`FA_UPDATE_GOLDEN=1` still works). A picture must pass three limits, not the mean error alone: the mean (0.004), the share of pixels more than 4/255 off (8 %) and the largest single-channel error (0.6, or 1.0 for goldens with text and thin edges, `expect_golden_edges`); the numbers come from measurements on Metal, llvmpipe and Direct3D 11 (hardware and WARP; `FA_GOLDEN_REPORT=1` prints them). The render, menus and mobile-export goldens share one helper, `engine/core/tests/golden_check.h`, tested in `engine/core/tests/test_golden.cpp`. `*.actual.png` files are git-ignored (the one that was committed is removed). docs/BUILDING.md, "Golden images".
