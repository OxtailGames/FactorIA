# What's new in FactorIA 0.21

The 0.21 releases, newest first. The newest version is in [CHANGELOG.md](../CHANGELOG.md).

## 0.21.0

FactorIA 0.21.0 (M91) makes the runtime independent of the renderer. Sprite animators and particles advance in the
fixed step, text is measured on the CPU with the renderer's fonts and shaping, and cameras and parallax follow the
simulation, so a run without graphics gives the same whole-world hash as one that draws, for every scene of every
example. A press reaches one `onFixedUpdate` step and one `onUpdate` frame whatever the frame rate. `Math` in scripts
gives the same bits on every platform, and a callback cut by the watchdog makes the run invalid. The audio callback
takes no lock and never waits, and when all voices play, the voice to replace is chosen by priority, then loudness.

### Changes

- **For game authors and AIs (M91.1a):** `SpriteAnimator` and `ParticleEmitter` advance in the engine's fixed step, not in the renderer, so a run with `--no-graphics` / `graphics=false` animates sprites (`frame`, `Sprite.region`, `clipEnded`, frame events) and ages, finishes and `autoDestroy`s particles exactly as a run that draws, and `entity.emitBurst(n)` / `particles.burst` work there too (the burst is born in the next simulation step; before, it was a no-op with a warning). The sheet's size is read from the image file or the packed atlas, never from a GPU texture. A clip or burst a script starts in a frame still shows in that frame's picture. A particle or animator no longer advances once per drawn frame but once per fixed step, so a window faster than `fixedHz` shows each step for several frames. `game.state_hash` takes `components` (an array of component type names) to compare two runs on those components alone; a mistyped name is an error with a suggestion.
- **For engine developers (M91.1a):** the state of the particles is a `ParticleStore` owned by the `World` (`World::particles()`, `fa/scene/particle_store.h`) and keyed by entity, where it was a process-wide map keyed by `Entity::bits()`: two live worlds (the editor's scene and its Play session) used to feed and clear each other's emitters. `World::clear()` and every scene load empty it. `update_sprite_animators(World&, float dt)` (`fa/scene/sprite_animator.h`) and `ParticleStore::update` run after `update_vfx` in `Engine::Impl::run_frame`, and again with `dt` 0 before a picture is drawn. The renderer keeps only camera and parallax in `Renderer::update`; `Renderer::advance_animators`, `emit_burst` and `reset_particles` and `SpriteAnimator::advancedPass` are gone, the job `render.particles` is `scene.particles`, and `clear_asset_cache` no longer clears particles. New tests: `engine/scene/tests/test_particle_store.cpp` (two worlds with the same entity bits), `engine/runtime/tests/sim_without_renderer_tests.cpp` (the world hash frame by frame with and without a renderer) and the ctests `example_<name>_graphics_same_hash` (one per example, every scene after 40 frames; Release builds). The whole-world hash of some example scenes still differs with a renderer: the size of UI text, the Parallax offset and `input.mouse.world` are measured by it (docs/ARCHITECTURE.md, "Animation").
- **For game authors and AIs (M91.2):** a press or a release reaches one `onFixedUpdate` step and one `onUpdate` frame, whatever the frame rate (an event a script injects while a step runs is also visible to the behaviours that read later in that same step, and then to the next step). A frame runs 0 to 5 fixed steps, and before this change `pressed`/`released` (actions, keys, mouse buttons, touches' `pressed`, gamepad buttons) were true in every step of the frame that carried them, so a jump read in `onFixedUpdate` fired up to 5 times on a slow frame, and one that arrived in a frame with no step was never seen by `onFixedUpdate`. Now the first step after the event sees it, once; an event that arrives in a frame with no step waits for the next step; a press and its release between two steps are both seen, in that order; a touch that lands and lifts between two steps shows once in `input.touches[].pressed`; an event a script injects with `game.input` during `onFixedUpdate` is seen by the next step; `input.consume(action)` no longer hides a second press of the same action. `mouse.wheel`, `mouse.delta`, `input.text` and Back follow the same rule, and holds (`down`, `value`, `axis`, `vector`, positions) are unchanged. `onUpdate`, `onLateUpdate`, the UI and `input.onBack` keep reading the frame they run in. Pressing Play (or Step) in the editor starts from a clean slate: a key tapped, a touch or text typed while the scene was only being edited is not a press in the first step. `game.step(n)` and `Engine::step` (one step per frame) behave as before. Recorded input and replays keep their format (events plus the `[dt, steps]` of each frame), but a recording made at variable frame times whose `onFixedUpdate` read `pressed` may now give a different result when replayed. `docs/SCRIPTING.md` has a table, "Which callback sees what (input)".
- **For engine developers (M91.2):** `Input` keeps two views of the edges (`fa/platform/input.h`, "TWO VIEWS"): index 0 for the frame (closed by `begin_frame()`), index 1 for the fixed step (closed by `end_fixed_step()`), with shared holds. `Input::FixedScope` (nestable, RAII) makes the queries answer for the fixed-step view; `Engine::run_frame` opens one per step. Every writer marks both views, so `apply_replay_entry`, the recorder and `game.input` are unchanged. `Input::touch_pressed(const Touch&)` replaces reading `Touch::pressedThisFrame` where the view matters (`Touch::pressedThisStep` is the other half). `consume_action` hides the press in the view being read and, in the other one, only while that view still has the press waiting. What arrives after the first `FixedScope` since the last `end_fixed_step()` goes to a third, late layer that `end_fixed_step()` makes the fixed view, so an event injected while a step runs reaches the next step once (the rest of that step may also read it). `Input::touches_in_view()` is the touch list of the view being read, including fingers that landed and lifted before that view looked (`touches()` stays the live state); text and consumed actions of a view nobody advances are capped (`Input::kMaxTextPerView`, one log line when it cuts). A step run inside another step (`Input::FixedScope` nested) does not close the outer one. `Input::discard_pending_edges()` forgets every edge nobody has read (the editor calls it when Play or Step starts); `reset_options()` also forgets a tap that is waiting to be seen.
- **For game authors and AIs (M91.1b):** a run without a GPU (`graphics=false`, `--no-graphics`, a CI machine with no display) lays out like a window: `ui.measureText`, `entity.bounds()` of a Text, the `fit`/`autoSize` of a `Panel` and the buttons in it, `Text.autoShrink` and the tooltip sizes shape the text on the CPU with the same fonts, HarfBuzz shaping, fallback chain, rich text and wrapping as the renderer, so a script that sizes a panel from `ui.measureText` gets the same width either way (it used to get 0.6 em per character and a warning). `input.mouse.world`, `camera.worldToScreen` / `screenToWorld` / `screenRay` / `cameraAt` and the offset of a `Parallax` layer follow the simulation and the camera without a renderer too. `game.state_hash` of the whole world, now including the live particles, is the same with and without graphics for every scene of every example. If the built-in font cannot be loaded the old 0.6 em approximation is used and one warning says so.
- **For engine developers (M91.1b):** `fa::TextMeasurer` (`fa/render/text_measure.h`) is the measurer without a renderer; it and `Renderer::measure_text` go through the GPU-free `FontSet` (render/src/font_set.h) that `Fonts::layout` also uses. `fa/scene/camera_geometry.h` holds the camera maths (`camera_geometry`, `CameraSet`, `update_parallax`, `pick_camera`) that the renderer's `CameraInfo` is built from; `rendering_cameras(world, &total)` skips cameras that are being destroyed. `ScriptHost` has two new virtuals, `text_measurer()` and `camera_set()`. `example_<name>_graphics_same_hash` fails on any difference of the whole-world hash (it only reported them before).
- **For game authors and AIs (M91.3):** `Math.sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, `exp`, `expm1`, `log`, `log2`, `log10`, `log1p`, `pow` (and `**`), `sinh`, `cosh`, `tanh`, `asinh`, `acosh`, `atanh`, `cbrt` and `hypot` in scripts are the engine's deterministic functions: the same bits on every platform (the C library's last bit differs between them), accurate to a few ulp (2 for `exp`/`log`, 3 for `sin`/`cos`, up to 6 for `tan`, `atan`, `atan2` and the hyperbolics), with `Math.pow(2, 10)`, `10 ** n` and `Math.log10(1e25)` and the other exact cases exact. Every script the engine runs gets them (game scripts, tests, tools and editor scripts: there is one QuickJS). A callback cut by the script watchdog now makes the run invalid and loud: an error naming the script and the callback, `factoria run --headless` exits 1 with `replayValid: false` and `watchdogCuts` in the report, a test that ran while a callback was cut fails, and `play.auto` reports an INVALID RUN. The report keeps the latest 100 cuts and counts all of them; the text of a failing test names the first five and says how many more. docs/SCRIPTING.md, "Runtime notes".
- **For engine developers (M91.3):** `fa/core/det_math.h` has `fa::det::f64::` (`exp`, `exp2`, `expm1`, `log`, `log2`, `log10`, `log1p`, `pow`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, the hyperbolics, `cbrt`, `hypot`) built only from `+ - * / sqrt`, and `float` versions of the new ones next to the existing frozen ones (`det::exp`, `pow`, `log`, `tan`, ...); a table of bit patterns and an accuracy test check them. The feel effects, animation clips, bounds, the model builders (bevel, remesh, SDF mesh, primitives, mesh surface and store), the VFX budget and the camera maths use them instead of `std::exp`/`pow`/`sin`/`cos`/`tan`, so a model or mesh built from those can differ from 0.20.0 by about one ulp. `engine/core/tests/test_det_scan.cpp` reads the simulation sources and fails on any C library transcendental; its file list (`kSimulationDirs`, `kSimulationFiles`, `kExempt`) is the place to add new simulation code. QuickJS's `Math` is routed to `f64` by a force-included header (`engine/script/quickjs_det/`), `external/` untouched. Replay hashes: particles and feel (`det_replay_hashes`) and a script that drives `Math`, 2D and 3D physics and nav (`det_probe_hashes`, `tools/cli/tests/determinism_probe.js`) are compared with committed values on the Linux, Windows and macOS jobs; the script one also runs in the Android emulator, the iOS simulator and the web smoke test (`scripts/det-hash-check.sh`). docs/ARCHITECTURE.md, "Determinism of the maths".
- **For game authors and AIs (M91.4):** voice stealing goes by priority, then loudness, never by age. When all 64 voices play, a new sound replaces the voice with the lowest priority, the quietest of those, if its own priority is higher, or the same and it is louder; otherwise it does not play and `audio.play` returns 0 (it used to replace the oldest sound that did not loop and always play). New `priority` (0..255, default 128) in `audio.play(path, { priority })`, `AudioSource.priority` and `PlayParams::priority`; music is never replaced, a video's sound and a `MusicPlayer` clip stinger have 192. `stats()` (and `game.state` under `audio`) count `voicesStolen`, `voicesRejected`, `underruns`, `underrunFrames`, `commandsDropped`, `settingsDropped` and `commandsCoalesced`. The music cache drops the songs nothing plays least recently played first. Everything else a game hears is unchanged. docs/SOUND.md, "Voice stealing".
- **For engine code (M91.4):** the audio callback takes no lock: every `Audio` call sends commands through a bounded lock-free ring (2048, with a staging queue of 8192 on the game side that drops the oldest plays and settings, never stops; a dropped setting is sent again from the game's copy when the queue has emptied, with no ramp (a long fade that was dropped becomes a step; a bus is found again by name, so a bus table swap during the stall does not move it, and a music player that lost its entity gets its last settings), and repeated pauses, effect resets, stops of everything and retunes of the music merge while the queue is long) and the mixer hands back what it is done with through another (4096), so the game side frees everything. Streamed sounds and music decode on `fa::jobs` into rings; a dry ring plays silence and is counted, never waits. `MusicPlayer` state reaches the game through a triple buffer and an event ring; song loads run on jobs with a device. `Audio::service()` commits, refills and drains once per frame (the engine calls it while paused too). Tests hold the API mutex while the callback mixes, count the callback's allocations with commands of every kind, and hammer it from four threads (checked with ThreadSanitizer when written; no CI job runs it). docs/SOUND.md, "The audio callback".
- **Polish of the simulation without a renderer (M91.P-sim):** a game with `localization.fallbackFonts` and no languages now gets those fonts in `ui.measureText` and `entity.bounds()` when it runs without graphics (the start language's fallback fonts were not applied then), and `camera.worldToScreen` / `screenToWorld` / `screenRay` answer right after a scene load (a script's `onStart`, before any frame has ended) with the scene's camera. With several cameras the `Parallax.offset` a script or `entity.bounds()` reads is always the one for the first camera, with or without a renderer; each camera still draws the layers shifted for itself. `game.state_hash` now includes the emitters' random sequence and emission accumulator, so a hash recorded by an earlier build of a scene with particles differs. For engine code: `Renderer::update(World&)` has no `dt`; `jobs::weighted_ranges` (`fa/core/jobs.h`) is shared by the particle step and gather; an animated texture's file is looked at once per frame, not twice.
