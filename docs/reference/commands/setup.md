# Commands: setup

## `setup.install` (modifies state)

Since 0.1.4.

Install what an export needs: the Android JDK + SDK, the players of other platforms, CMake, the AppImage tools, sokol-shdc, the VS Code debugger extension, ffmpeg, the app launcher, the DirectStorage DLLs, the NVIDIA Streamline, Intel XeSS and AMD FidelityFX DLLs (or open Xcode's App Store page).

Capabilities: read, writeAnywhere, network, process

The user's call, not an AI's: it installs software outside the project and accepts licenses, so an MCP client or an AI agent gets `capability_denied`. Call setup.status and tell the user to press the editor's File > Set Up This Computer... button or run `factoria setup <component>`. Run by the user, it downloads and installs one component into $FACTORIA_HOME (default ~/.factoria) and returns {component, changed, steps[], paths, nextSteps[], warnings[], seconds}; every step says whether it was installed or skipped. Hundreds of megabytes (setup.status: installSizeMb), minutes. `android`: JDK 21 and the Android SDK, saved in ~/.factoria/export.json so `project.export` finds them. It REFUSES with `license_required` until acceptLicenses is true, which only the user who has read the Android SDK license (setup.status components[].licenses[].text) sets. Example: {"component":"android","acceptLicenses":true}.

`android` in full: JDK 21 (Eclipse Temurin) and the Android SDK command-line tools, platform-tools, platform 36 and build-tools 35.0.0 (the SDK found on this computer is reused, except Unity Hub's). `players`: the factoria_player of the other desktop OSes plus the prebuilt mobile libraries, for exports to other platforms without building anything; from the GitHub release of this factoria's version (a development build ahead of the last release takes the newest release's players and warns that their build fingerprint will not match, so an export needs allowPlayerMismatch; code `no_release` only when even the newest release cannot be read); platforms narrows it (windows, linux, macos, mobile, web). `webplayer`: builds the web player from the checkout this factoria was built from (CMake preset web-release) into build/web-release/player, where the web export looks first; uses an Emscripten SDK it finds ($EMSDK, emcc on PATH, .cache/emsdk, ~/emsdk) or fetches the pinned one (6.0.10, about 1 GB) into the checkout's .cache/emsdk; takes several minutes, so ask the user first; skipped when the player there is of this factoria's build. `cmake`: CMake 3.31 from Kitware (macOS only, for iOS exports) unless 3.24+ is found; force installs it anyway. `xcode` (macOS): cannot be installed by a program: it opens Xcode's App Store page and returns the steps the user must do (some need their password). `appimage` (Linux x86_64): appimagetool 1.9.1 and the AppImage runtime from github.com/AppImage, about 16 MB, into $FACTORIA_HOME/tools/appimage. `shaders`: the pinned sokol-shdc (github.com/floooh/sokol-tools-bin, 8-12 MB depending on the computer) into $FACTORIA_HOME/tools/sokol-shdc/<commit>/, for source builds and editor-less setups; downloads of factoria carry it. `vscode`: copies the VS Code extension built into factoria (the script debugger, docs_read {"name":"debugging"}) to ~/.vscode/extensions/oxtailgames.factoria-<version>/ and to VS Code Insiders, VSCodium and Cursor when they exist, records the path of this factoria next to it and removes older versions; nothing is downloaded, so it is fast and safe to run without asking. `ffmpeg`: the static ffmpeg 6.0 build of github.com/eugeneware/ffmpeg-static (GPL, with libx264 and AAC; 19-28 MB depending on the computer) into $FACTORIA_HOME/tools/ffmpeg/<release>/, so `factoria run --record-video trailer.mp4` works without installing ffmpeg by hand; skipped when an ffmpeg is already found. `launcher` (macOS, Linux): writes the app that opens this factoria's editor with the FactorIA icon (~/Applications/FactorIA.app, or factoria.desktop + its icon under ~/.local/share), so it can be kept in the Dock or the application menu; nothing is downloaded, so it is fast and safe to run without asking; an existing launcher is rewritten in place (a Dock item stays valid). `directstorage`: the NuGet package Microsoft.Direct3D.DirectStorage 1.3.0 (about 3 MB, Microsoft's license in LICENSE.txt next to the DLLs), of which the x64 dstorage.dll and dstoragecore.dll are kept in $FACTORIA_HOME/tools/directstorage/<version>/; a Windows release export with export.pack.directStorage copies them next to the game, which then reads the gdeflate blocks of game.pak through DirectStorage; any computer can install it, a Mac or Linux that exports for Windows too. `streamline` (NVIDIA Streamline 2.14.16, about 280 MB), `xess` (Intel XeSS 3.0.2, about 77 MB) and `fidelityfx` (AMD FidelityFX SDK 2.4.0, about 160 MB) download the vendor's own release (SHA-256 checked against FactorIA's pin) and keep only the redistributable x64 DLLs with their license texts in $FACTORIA_HOME/tools/<id>/<version>/ (only the listed files are unpacked, each checked against its own pinned SHA-256, and an export checks them again; the install needs about 550, 300 and 200 MB of free disk space while it runs; folders of older versions are removed); each REFUSES with `license_required` until acceptLicenses is true (force installs again, so it asks again), which only the user who has read the license (setup.status components[].licenses[].text, which starts with what it asks of the game) sets; a Windows export copies the DLLs next to a game whose render settings can use them (export.pack.vendorSdks, default "auto"). Every download is checked against the publisher's checksum (error code `checksum_mismatch` installs nothing). Other error codes: network, cancelled, unsupported, invalid_argument, failed; the data of the error holds the steps done so far.

| Argument | Type | Required | Description |
|---|---|---|---|
| `component` | string ["android","players","webplayer","cmake","xcode","appimage","shaders","vscode","ffmpeg","launcher","directstorage","streamline","xess","fidelityfx"] | yes | What to install: android (JDK + Android SDK), players (other platforms' factoria_player + mobile libraries), webplayer (builds the web player from the engine checkout), cmake (iOS export), xcode (guidance only), appimage (appimagetool + runtime for the Linux AppImage export; Linux x86_64 only), shaders (sokol-shdc, compiles custom materials), vscode (the script debugger extension for VS Code, Insiders, VSCodium and Cursor), ffmpeg (turns --record-video recordings into .mp4), launcher (the app that opens the editor, with the FactorIA icon), directstorage (the DirectStorage DLLs a Windows export ships with the game), streamline (NVIDIA Streamline: DLSS and Reflex DLLs), xess (Intel XeSS DLLs), fidelityfx (AMD FidelityFX FSR DLLs). |
| `acceptLicenses` | boolean | no | android, streamline, xess, fidelityfx: the user has read the license (setup.status components[].licenses) and agreed to it. Without it the install refuses with license_required. Never set it without asking the user. Default false. |
| `platforms` | array | no | players: which players to install (default: every desktop OS but this one, plus the mobile libraries when this factoria has none next to it). "web" installs the web export's player (factoria_player.js + .wasm); every download carries it next to factoria, so it is only fetched when asked for. |
| `force` | boolean | no | android, cmake, players, webplayer, ffmpeg, launcher, directstorage, streamline, xess, fidelityfx: install again even when it is found (a JDK or CMake that is already there is used otherwise). Default false. |

## `setup.status` (modifies state)

Since 0.1.4.

Check what this computer has for exporting: the Android JDK and SDK, the players of other platforms, CMake, Xcode, the AppImage tools, sokol-shdc, the VS Code debugger extension, ffmpeg, the FactorIA app launcher, the DirectStorage DLLs of Windows games, the vendor SDKs (NVIDIA Streamline, Intel XeSS, AMD FidelityFX) a Windows game ships with.

Capabilities: read, network, process

Returns {home, host, components[]}; each component is {id, title, state, details, paths, problems[], installSizeMb, licenses[], canInstall}. Example: {"component":"android"}.

Components: `android` (JDK + Android SDK for APK/AAB exports), `players` (the factoria_player of the other desktop OSes and the prebuilt Android/iOS libraries, from the GitHub release of this factoria's version), `webplayer` (the web player built from the engine checkout this factoria was built from, for a development build: installed when build/web-release/player holds one of this build; unsupported without the checkout) `cmake` (3.24+, for the iOS export on a Mac), `xcode` (macOS: status only, it cannot be installed by a program) and `appimage` (appimagetool and the AppImage runtime, Linux x86_64 only: what `project.export` {platform: linux, format: appimage} builds an AppImage with) `shaders` (sokol-shdc, the shader compiler of custom materials: $SOKOL_SHDC, the one next to factoria or the pinned one under home/tools/sokol-shdc/) `vscode` (the FactorIA debugger extension in ~/.vscode/extensions and the other VS Code based editors' folders: installed when this factoria's version is there; docs_read {"name":"debugging"}) `launcher` (an app that opens the editor with the FactorIA icon: ~/Applications/FactorIA.app on macOS, a .desktop entry on Linux; unsupported on Windows, where the installer adds a Start menu entry; partial when it opens another factoria or its files are out of date) and `ffmpeg` (what `factoria run --record-video trailer.mp4` converts its recording to H.264 + AAC with: $FACTORIA_FFMPEG, "publish": {"ffmpeg"} of export.json, PATH or the one under home/tools/ffmpeg/) and `directstorage` (the x64 dstorage.dll and dstoragecore.dll a Windows release export with export.pack.directStorage puts next to the game, under home/tools/directstorage/<version>/; any computer can hold them, but off Windows it is unsupported: nothing there needs it, and it is installed only when asked for by name) and the vendor SDKs `streamline` (NVIDIA Streamline: DLSS, DLSS Ray Reconstruction, DLSS Frame Generation, Reflex), `xess` (Intel XeSS, XeSS-FG, XeLL) and `fidelityfx` (AMD FidelityFX: FSR upscaler and frame generation): the vendors' redistributable x64 DLLs a Windows export copies next to a game whose render settings can use them (export.pack.vendorSdks), under home/tools/<id>/<version>/, installed on any computer and unsupported off Windows like directstorage. state is installed | missing | partial | unsupported (nothing to do on this computer). problems[] says what is missing and how to fix it; `setup.install` fixes everything except Xcode. `licenses` (android, streamline, xess and fidelityfx) holds {id, title, text}: the full license the user must read and agree to before `setup.install` with acceptLicenses. Android lists it while it is not accepted yet; a vendor SDK lists it, installed or not (a reinstall asks again), only when that component is asked for (`component`), because it is fetched on its own. The only network request is the fetch of that license text (fetchLicenses false skips it; without `component` only Android's is fetched). Everything installed lives under `home` ($FACTORIA_HOME, default ~/.factoria). Details: docs_read {"name":"exporting"}.

| Argument | Type | Required | Description |
|---|---|---|---|
| `component` | string ["android","players","webplayer","cmake","xcode","appimage","shaders","vscode","ffmpeg","launcher","directstorage","streamline","xess","fidelityfx"] | no | Only this component (default: all of them). |
| `fetchLicenses` | boolean | no | Download the license text (a network request): Android's when it is not accepted yet; a vendor SDK's (streamline, xess, fidelityfx) when `component` names it, installed or not. false = skip it (a polling UI). Default true. |
