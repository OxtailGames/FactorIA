# Components: 3D

## Animator

Since 0.2.0.

Plays animation clips: the skeletal clips of a skinned glTF model (the model of the MeshRenderer on the same entity, or `model`), or, when there is no glTF model, the keyframed 2D clips of `clips` (*.anim.json files that animate fields of this entity and its children: position, rotation.z, color.a, Sprite.region...). One clip at a time with cross-fades, clip events, an optional small state machine (`params`, `states`, `transitions`) and, for 2D clips, `layers`. It runs in the fixed step, so headless runs and replays match. Scripts: entity.animator.play("Run", 0.2), .set("speed", 3), .stop(); events reach world.on(name, ...).

| Field | Type | Default | Description |
|---|---|---|---|
| `model` | string | `""` | Project-relative .gltf/.glb path with the skin and the clips. Empty = the `mesh` of the MeshRenderer on the same entity (usual case: leave it empty). |
| `clip` | string | `""` | Name of the clip playing now: a glTF animation, or a key of `clips` (see entity.animator.clips). Assigning it at run time switches clips with a cross-fade of `fade` seconds. Empty = bind pose (the model as exported), or, for 2D clips, the fields rest where they were before the first clip drove them. |
| `clips` | json | `{}` | Clip files, an object name -> project-relative *.anim.json path, such as {"walk": "anim/hero_walk.anim.json", "idle": "anim/hero_idle.anim.json"}. Two kinds (docs/ANIMATION.md). 2D clips ("2D clips") are used when the Animator has no glTF `model` (and the MeshRenderer on the entity is not a glTF): they animate fields of this entity and its descendants (found by EntityInfo name), a runtime pose that scene.save does not write. 3D bone clips (format factoria.anim3d/1, "3D bone clips") are used when the Animator plays a skinned glTF (a rig.bake .glb): they pose its bones, and sit next to the model's own animations. `clip`, `states` and play() name these either way. (since 0.7.0) |
| `speed` | float | `1.0` | Playback speed multiplier: 1 = authored speed, 2 = twice as fast, 0 = frozen. Range 0.0..100.0. |
| `loop` | bool | `true` | true = start over when the clip ends. false = stop on the last pose and send the `anim.finished` event. |
| `playing` | bool | `true` | Set false to pause, true to play. |
| `fade` | float | `0.2` | Cross-fade seconds used when `clip` is changed by assignment (play() takes its own). Range 0.0..60.0. |
| `params` | json | `{}` | State machine parameters and their start values, an object such as {"speed": 0, "grounded": true}. Numbers and booleans. Scripts change them with animator.set(name, value); transitions read them. |
| `states` | json | `{}` | State machine states, an object name -> {clip, loop (default true), speed (default 1), onEnter}. `onEnter` is the name of a game event sent when the state starts (world.on). Example: {"idle": {"clip": "Idle"}, "run": {"clip": "Run", "onEnter": "started_running"}}. |
| `transitions` | json | `[]` | State machine transitions, an array checked in order every step; the first that matches fires. Each: {from (a state, or "*"/omitted = any), to, when, fade (seconds, default 0.2), onFinish}. `when` is conditions joined by "&&": `speed > 0.1`, `grounded`, `!grounded`, `hp <= 0` (operators > >= < <= == !=). A parameter set with animator.trigger(name) is true for one step. onFinish: true fires when the current non-looping clip ended (alone or together with `when`). |
| `layers` | json | `[]` | 2D clips only: layers played at the same time as the main clip, an array of {name, clip \| states (with transitions and state, like the Animator's own), weight (0..1, default 1), mode ("override" blends toward the layer's pose, "additive" adds the layer's change from its first pose; default override), mask (paths such as ["body/arm_l"]: the layer drives only the parts under them; empty = all), speed (default 1), loop}. Layers apply in order over the main clip. A layer at weight 0 is not playing; it starts from its first pose when its weight rises. Example: [{"name": "arms", "clip": "shoot", "mask": ["body/arm_l"]}]. (since 0.7.0) |
| `events` | json | `[]` | Clip events, an array of {clip, time, name?, feel?}: when the clip's time passes `time` (seconds) the game event `name` is sent once per loop, with data {id, clip, time}; listen with world.on(name, fn). `feel` (one action object or an array, the form of `feel.do(action)`: shake, hitStop, flash, knockback or push, squash, spawn, sound; docs/GAME_FEEL.md, "Effects as data") runs game feel actions on this entity at the same moment. An event needs `name` or `feel`. Example: [{"clip": "Walk", "time": 0.3, "name": "footstep"}, {"clip": "Attack", "time": 0.2, "feel": {"action": "hitStop", "duration": 0.06}}]. |
| `state` | string | `""` | State machine: the state the animator is in (the start state when set in the scene; empty = the first state of `states`). Updated as transitions fire. |
| `time` | float | `0.0` | Runtime state: seconds into the current clip. Assigning it seeks (no events fire). Runtime-only (not saved). |
| `values` | json | `{}` | Runtime state: current value of every state machine parameter. Runtime-only (not saved). |

## Decal

Not released yet (on main after 0.32.0).

A texture projected onto the 3D meshes that stand inside the box of this entity: bullet holes, blood, graffiti, dirt, road markings, the cracks of a wall. The box is the Transform's world matrix applied to a cube of side 1 (scale = size in metres); the decal projects along the entity's forward (-Z), its image is upright when seen from +Z (the top of the image is +Y). Every mesh with receiveDecals inside the box takes it, the albedo blended over the surface and the normal bent, with no extra geometry and one draw per mesh. Up to 256 decals are drawn at once (the ones that reach the view). It is drawn by the lit forward shaders only: a mesh drawn by a custom shader must call fa_apply_decals (docs/shaders/SHADERS_LIGHTING.md). Not the same as the decals of a model's `texturing` section, which bake a picture into the UV texture of one model. The textures of all the decals share one atlas; see docs/rendering/RENDERING_LIGHTING.md, "Decals".

| Field | Type | Default | Description |
|---|---|---|---|
| `albedo` | asset (texture) | `""` | The colour texture painted onto the surface (its alpha is the shape of the decal). Empty = the decal is a flat patch of `color` over the whole box. The texture is read as sRGB colour. |
| `normal` | asset (texture) | `""` | Optional normal map (tangent space, +Y up, the file is read as linear data) that bends the normal of the surface under the decal (bullet dents, bumpy paint, a raised sticker). Empty = the normal stays. |
| `color` | color | `[1.0,1.0,1.0,1.0]` | Tint multiplied with the albedo texture; its alpha is multiplied with the texture's alpha. White (default) leaves the texture as it is. |
| `opacity` | float | `1.0` | 0..1: strength of the whole decal, for fading it out (a bloodstain that dries). Range 0.0..1.0. |
| `normalStrength` | float | `1.0` | 0..4: how strongly `normal` bends the surface (1 = the map as painted, 0 = not at all). Range 0.0..4.0. |
| `angleFade` | float | `60.0` | Degrees 0..90. The decal is at full strength while the angle between the surface's normal and the projector's axis (the decal looks along its local -Z) is under this; beyond it the strength falls as cos(angle) / cos(angleFade) and reaches 0 only when the surface is edge-on (90 degrees), so a smaller value keeps the decal from smearing along walls seen at a slant. 90 keeps full strength until the surface is edge-on. Default 60. Range 0.0..90.0. |
| `sortOrder` | int | `0` | Decals are drawn in ascending order of this value (a larger one lands on top of a smaller one); equal values keep the order in which the world visits its Decal components (a stable sort). When more than 32 decals cover one cluster of the view the lowest values are kept. Range -1000000..1000000. |
| `layers` | int | `0` | Bit mask 0..65535 of the MeshRenderer.decalLayer values this decal draws on: bit 0 is layer 0, bit 1 layer 1, up to bit 15. 0 (default) = every layer. Range 0..65535. |

## IK3D

Since 0.16.0.

3D inverse kinematics on the skinned model of the Animator on the same entity (docs/ANIMATION.md, "3D IK"). Every fixed step, after the Animator has posed the bones, the `solvers` adjust them and the model is drawn with the result: a hand that reaches a lever (twoBone, with a pole vector for the elbow), a head that looks at something within limits (lookAt), feet that stand on uneven ground with the pelvis lowered to fit (foot, one ray per foot through the physics world). Solvers apply in order. The bones are found by the canonical names of rig.bake (docs/RIGGING.md). Deterministic; the animated pose is never changed, the solvers start from it every step.

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | bool | `true` | false: the animated pose is drawn untouched. |
| `weight` | float | `1.0` | 0 to 1. 0 = the animated pose, 1 = the solved pose; multiplies the weight of every solver. Fade it in while a hand holds something, out when it lets go. Range 0.0..1.0. |
| `solvers` | json | `[]` | An array of solvers, applied in order. Every solver has "type", an optional "name", "weight" (0..1, default 1) and "enabled" (default true). A target is an entity id or name ("player"), a world position [x, y, z], or {"entity": "player", "offset": [0, 1.6, 0]} (the offset in world units). twoBone: {root, mid, end} bone names (or limb "arm"\|"leg" with side "l"\|"r"), target, optional pole (the elbow or knee bends towards it). lookAt: {bone, target, forward (the bone's axis that looks: "+z" by default), yawLimit (70), pitchLimit (45), turnSpeed (degrees per second, 360; 0 = snap)}. foot: {side "l"\|"r" (or thigh, shin, foot), footHeight (height of the ankle above the sole; default = its rest height), alignToGround (true), maxFootAngle (30)}; all foot solvers act together on the lowest ground under them. Example: [{"type": "lookAt", "bone": "head", "target": "player"}, {"type": "foot", "side": "l"}, {"type": "foot", "side": "r"}]. Problems are logged once; `ik3d.check` lists all of them. |
| `pelvis` | string | `"root"` | Foot placement: the bone moved vertically so the feet reach lower or higher ground ('root' = the hips of every rig.bake template). |
| `rayUp` | float | `0.5` | Foot placement: world units above the animated ankle where the ground ray starts. Range 0.0..100.0. |
| `rayDown` | float | `0.8` | Foot placement: world units below the animated ankle the ray reaches. No hit = the foot is left as animated. Range 0.0..100.0. |
| `groundMask` | int | `-1` | Foot placement: bitmask of the physics layers the ray hits (-1 = all). The colliders of this entity are ignored. |
| `pelvisSmooth` | float | `0.1` | Foot placement: seconds the feet and the pelvis take to settle on a new ground height, so a step does not pop (0 = at once). Range 0.0..5.0. |
| `maxPelvisDrop` | float | `0.4` | Foot placement: the most the pelvis goes down, in model units. A leg that cannot reach stretches straight. Range 0.0..10.0. |
| `maxPelvisRise` | float | `0.15` | Foot placement: the most the pelvis goes up, in model units. Range 0.0..10.0. |
| `status` | json | `[]` | Runtime state: one object per solver, {name, type, active, ...}: twoBone adds reached and error (distance of the end to the target, model units), lookAt clamped, yaw and pitch (degrees turned), foot contact (0 in the air, 1 planted), lift (ground offset, model units), reached and error. A solver with problem:true did not parse. Read-only. Runtime-only (not saved). |

## Light

A light source for 3D meshes. A directional light shines along the entity's forward direction (-Z rotated by the Transform), point and spot lights shine from the entity's position, an area light from a rectangle, disc or tube around it. A view lights with up to 1024 lights at once (32 of them directional): each fragment reads only the lights of its cluster. The fields after castShadows belong to the lighting of M73; the doc string of each says whether the renderer draws it yet (docs/rendering/RENDERING_LIGHTING.md).

| Field | Type | Default | Description |
|---|---|---|---|
| `type` | enum: directional \| point \| spot \| area | `"directional"` | directional: sun-like, infinite distance. point: radiates in all directions. spot: cone along forward. area: a rectangle, disc or tube (`shape`, `size`) that lights with soft highlights and a diffuse term that follows its extent (linearly transformed cosines; drawn since M73.1b). Far from a surface it lights like a point light of the same `intensity`; near it, it is bounded, never infinitely bright. Materials with a lighting() or light() hook and full shaders get it as the light of one point of the emitter (the nearest to the reflection of the view), not the whole shape. |
| `color` | color | `[1.0,1.0,1.0,1.0]` | Light color. |
| `intensity` | float | `1.0` | Brightness multiplier. Range 0.0..1000.0. |
| `range` | float | `10.0` | Point/spot only: distance in meters where the light fades to zero. Range 0.01..100000.0. |
| `spotAngle` | float | `30.0` | Spot only: cone half-angle in degrees. Range 1.0..89.0. |
| `castShadows` | bool | `false` | Cast shadows (M73.2). A directional light shadows with cascades (the first one that casts: see SceneSettings.shadowCascades); a spot light with one perspective map and a point (or area) light with six, an area light from the centre of its emitter (with shadowFilter pcss the penumbra is as wide as the emitter: see shadowSoftness), all in the same atlas (SceneSettings.shadowAtlasSize). The point and spot lights that cast share a budget per frame: the most important for the camera (brightness, range, distance) keep their maps, get smaller ones when the atlas is full and lose the shadow when even that does not fit (a warning names the fix once). |
| `innerAngle` | float | `0.0` | Spot only: half-angle in degrees of the cone inside which the light is at full strength; it fades to nothing at spotAngle (a larger value is used as spotAngle). 0 (default) = the cone fades as it does today (a smoothstep of the cosine from the edge of the cone inwards). Drawn since M73.1a. Range 0.0..89.0. (not released yet, on main after 0.32.0) |
| `shape` | enum: rectangle \| disc \| tube | `"rectangle"` | Area lights only: the shape of the emitter. rectangle and disc lie in the entity's X and Y axes and emit from their front, the side the entity's forward direction points to (nothing behind); a tube is a line of light along the entity's X axis and emits all around. Drawn since M73.1b. (not released yet, on main after 0.32.0) |
| `size` | vec2 | `[1.0,1.0]` | [width, height] in metres of a rectangle, [diameter, -] of a disc (x), [length, thickness] of a tube (area lights); of a directional light with a cookie, the metres one copy of the cookie covers along the light's X and Y axes (the cookie repeats over the world, starting at the world origin). Other lights ignore it. Range 0.001..1000.0. (not released yet, on main after 0.32.0) |
| `cookie` | asset (texture) | `""` | A texture the light projects (window blinds, a leaf canopy, a flashlight's shape). A spot light projects it through its cone (the edge of the cone is the edge of the picture); a directional light projects it straight along its forward direction, repeated every `size` metres. Its colour multiplies the light's (premultiplied by its alpha); the texture is resampled to 254 x 254 texels. A point light projects it all around: the picture is read as an equirectangular panorama (the centre in the light's forward direction), stored as six faces of 254 texels, so 1024 x 512 or more is useful. Area lights ignore it (a warning says so once). Empty = none. Drawn since M73.1b; render.supports lightCookies. (not released yet, on main after 0.32.0) |
| `ies` | asset (any) | `""` | An IES profile (.ies file, LM-63 photometric type C; import it with assets.import) with the measured light distribution of a real lamp, on a point or spot light. The profile's nadir points along the entity's forward direction. The table is divided by its peak, so `intensity` stays the brightness at the brightest direction and the file only shapes the light. Empty = the plain distribution. Drawn since M73.1b; render.supports iesProfiles. (not released yet, on main after 0.32.0) |
| `shadowResolution` | int | `0` | Texels per side of each shadow map of this light, 0..4096. Directional: per cascade (a value under 128 is raised to 128, rounded down to a power of two); 0 (default) = the engine picks, 2048 for one cascade and 1024 for several. Point and spot: per tile (a point light has six, one per face), 64..2048 rounded down to a power of two; 0 = from the distance to the camera (1024, 512 per face of a point light, smaller as the camera moves away from the light's range). When the maps do not fit the atlas (SceneSettings.shadowAtlasSize) the largest are halved, the least important first, down to 128 for the sun and 64 for the others. Range 0..4096. (not released yet, on main after 0.32.0) |
| `shadowBias` | float | `0.0` | Depth offset of the shadow test in metres along the light, 0..1, against shadow acne; it grows with the slope of the surface. 0 (default) = the engine's own bias, 1.5 texels of the map (of the tile at the surface's distance for a point or spot light). Range 0.0..1.0. (not released yet, on main after 0.32.0) |
| `shadowNormalBias` | float | `0.0` | Offset along the surface normal, in metres 0..1, against shadow acne on slopes. 0 (default) = the engine's own, 1.5 texels of the map (of the tile at the surface's distance for a point or spot light). Range 0.0..1.0. (not released yet, on main after 0.32.0) |
| `shadowFilter` | enum: pcf \| hard \| pcss | `"pcf"` | How the edge of the shadow is filtered. pcf (default): a small fixed blur. hard: no filtering, the sharpest and cheapest. pcss: a penumbra that grows with the distance to the caster, sized by shadowSoftness. (not released yet, on main after 0.32.0) |
| `shadowSoftness` | float | `1.0` | With shadowFilter pcss: the size of the light for the penumbra, 0..10 (1 = the usual: a sun about 6 degrees wide; for an area light 1 = the size of its emitter, `size`). 0 = the narrowest penumbra, a plain PCF of 1.5 texels (use shadowFilter hard for a hard shadow). Range 0.0..10.0. (not released yet, on main after 0.32.0) |
| `shadowDistance` | float | `0.0` | How far from the camera, in metres, this light draws shadows. Directional: the end of the last cascade. Point and spot: the shadow fades out between 75% of this distance and this distance from the camera, and a light farther away than this plus its range gets no map at all (it costs nothing). 0 (default) = the scene's SceneSettings.shadowDistance; when that is 0 too, a point or spot light has no limit. Range 0.0..100000.0. (not released yet, on main after 0.32.0) |
| `mode` | enum: realtime \| baked \| mixed | `"realtime"` | realtime (default): lit every frame. baked: its light is computed once into the lightmaps (lightmap.bake) and an entity lit by a lightmap no longer gets it at run time; an entity with no lightmap entry is still lit by it every frame, so nothing goes dark before the bake (with castShadows, a point or spot light of this mode gets a shadow map only while a mesh with no lightmap is within its range: the lightmapped ones skip it). mixed: lit every frame like a realtime light, with shadows (its bounce light in the lightmaps and the light probes for moving objects: M73.4c and M73.4d). (not released yet, on main after 0.32.0) |
| `volumetric` | float | `0.0` | Strength 0..10 of this light's shafts in the volumetric fog (SceneSettings.fogDensity must be above 0). 0 (default) = no shafts. No effect yet: M73.5 brings it. Range 0.0..10.0. (not released yet, on main after 0.32.0) |

## MeshRenderer

Draws a 3D mesh with a PBR material (GGX highlights, sky reflections, normal maps; glTF materials are read). Needs a perspective Camera and (unless unlit) a Light to be visible.

| Field | Type | Default | Description |
|---|---|---|---|
| `mesh` | string | `"cube"` | Built-in shape name ("cube", "sphere", "plane", "cylinder", "capsule", "cone", "quad") or a project-relative path to a .gltf/.glb model (e.g. "assets/models/ship.glb"), or the `id` ("mesh:3") of a procedural mesh a script made with mesh.create() (it lives as long as the scene: a scene load releases it). |
| `texture` | asset (texture) | `""` | Base color texture. Empty = none (or the glTF material). "target:<name>" shows the live picture of the Camera whose `renderTarget` is that name (a screen, a mirror, the page of a book; docs/RENDERING.md, "Render targets"). A pointer over the mesh reaches the Interactables of that camera. |
| `normalMap` | asset (texture) | `""` | Tangent-space normal map (glTF convention: +Y up, the usual blue-ish image) that adds small-scale relief without more triangles. Empty = none (or the glTF material's normalTexture). Replaces the glTF one when set. Takes "target:<name>" like `texture`. (since 0.2.0) |
| `normalScale` | float | `1.0` | How strong the normal map is: 0 = flat, 1 = as authored. Range 0.0..4.0. (since 0.2.0) |
| `color` | color | `[1.0,1.0,1.0,1.0]` | Base color, multiplied with the texture. |
| `metallic` | float | `0.0` | 0 = plastic/stone, 1 = metal. glTF models use their own metallic value and metallicRoughnessTexture instead. Range 0.0..1.0. |
| `roughness` | float | `0.6` | 0 = mirror-smooth, 1 = fully rough/matte. glTF models use their own roughness and metallicRoughnessTexture instead. Range 0.0..1.0. |
| `emissive` | color | `[0.0,0.0,0.0,1.0]` | Light emitted by the surface regardless of lighting (glow). Black = none. |
| `emissiveStrength` | float | `1.0` | HDR multiplier of the emitted light: `emissive` (and the glTF model's own emissive color) times this. 1 = as written; above 1 the glow is brighter than white, which a color array cannot say (an array with a channel over 1 is read as 0..255), and with `Camera.bloom` it makes a bigger, brighter halo. The screen still shows at most white. Meshes that differ only here are not drawn in the same batch. Range 0.0..100.0. (since 0.23.0) |
| `unlit` | bool | `false` | true = ignore lighting and draw the flat base color. |
| `castShadows` | bool | `true` | Cast shadows from shadow-casting lights. |
| `receiveShadows` | bool | `true` | Receive shadows from shadow-casting lights. |
| `uvScale` | vec2 | `[1.0,1.0]` | Texture tiling [u, v]; 2 repeats the texture twice. |
| `material` | asset (material) | `""` | Project-relative path of a custom material, a *.material.json file (e.g. "materials/water.material.json"), or "" (default) for the standard PBR material. The material file names a GLSL snippet whose surface() changes what the standard material computed (albedo, alpha, normal, emission...) and whose optional vertex() moves the vertices (it can sample the material's textures), and declares its params, textures, lighting (pbr, unlit, or custom: the snippet's light() shades each light) and alphaMode (opaque, clip or blend). The `material.info` command lists a material's params and textures; `shader.compile` compiles it and reports errors with file:line. The material's alphaMode wins over color.a < 1; `unlit` true forces unlit lighting. A material that does not compile draws magenta and logs why. Guide with worked examples: docs/SHADERS.md (`factoria docs read shaders`). (since 0.2.0) |
| `materialParams` | json | `{}` | Per-entity overrides of the material's params and textures, as an object keyed by the name declared in the material file: numbers for float params, arrays for vectors and colors ([r, g, b, a]), project-relative paths for textures (a path, or "target:<name>" for the live picture of a render-target camera). Example: {"glow": [1, 0.2, 0, 1], "mask": "textures/leaf.png"}. Unnamed params keep the material's defaults. A material that declares "buffers" takes the id of a compute buffer for each, as an integer: {"particles": 3} (see instances). An entity without overrides batches with the others that share the material. (since 0.2.0) |
| `materialColors` | json | `{}` | Per-material colours of a glTF model, an object keyed by glTF material name: {"Body": [0.2, 0.8, 0.7, 1]}. The colour REPLACES that material's baseColorFactor on its sub-meshes (the texture still multiplies it) and `color` still multiplies the result, so `color` stays the tint of the whole model. Materials not named keep their own colour. Names come from the model (the sub-mesh keeps its material name from import); `factoria validate` checks them and suggests the right one for a typo. Ignored by built-in shapes. Entities that differ only in materialColors are drawn in separate batches. (since 0.3.0) |
| `lods` | json | `[]` | Lower-detail meshes the renderer swaps in with distance, an array ordered from the nearest: [{"mesh": "assets/models/lamp.lod1.glb", "distance": 12}, {"mesh": "assets/models/lamp.lod2.glb", "distance": 30}]. From the camera distance (metres, between the camera and the entity's origin) of an entry on, that mesh is drawn instead of `mesh`; farther entries win. `mesh` itself is the full-detail one. `model.bake` writes these files and the prefab that sets this field when a model document has gameReady.lods (docs/MODELING.md). An entry that is not an object with a `mesh` string and a `distance` number is ignored. Colliders and picking keep using `mesh`. Entities that differ only in their LOD are drawn in the batch of the mesh they show. (since 0.16.0) |
| `instances` | int | `0` | 0 (default) = a normal draw of the mesh. N > 0 = ONE draw of N instances of the mesh, whose data the material reads from compute buffers (the material declares "buffers", and materialParams gives the id of a compute buffer for each: {"particles": 3}; docs/shaders/SHADERS_COMPUTE.md, "Drawing from a compute buffer"). The material's vertex() gets the instance number as fa_instance_index (0..N-1) and places each instance; the entity's Transform is the base every instance is placed relative to (fa_model in a full shader). Every buffer the material reads must hold at least N elements (otherwise the entity is not drawn and the log says why), and N is at most 16777216: size the buffers for it. The instances cast shadows and enter the depth prepass like the mesh does; an entity with instances is drawn on its own and never batched with others. Needs a material with buffers, on Metal, D3D11 or OpenGL 4.3 (not GLES3, WebGL2 or macOS OpenGL); with another material, or none, instances > 0 draws nothing and logs why. Range 0..16777216. (since 0.32.0) |
| `instanceBounds` | float | `0.0` | For a material with buffers only: the half-extent, in the entity's local metres, of the box around the entity that holds every instance (the instances are placed by the GPU, so the CPU cannot know where they are). The entity is skipped, with its shadows, when that box (scaled by the Transform) is outside the camera's view. 0 (default) = never culled by the camera, always drawn: safe, but it costs GPU time for an entity that is off screen. Range 0.0..1000000.0. (since 0.32.0) |
| `lightmapScale` | float | `1.0` | Resolution of this mesh in the baked lightmap, as a multiple of the scene's lightmap density (1 = the scene's).
